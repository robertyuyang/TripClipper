# select-review 只读选片验收页设计

## 背景与目标

选片任务当前以 `state.json` 作为核心结构化结果。它适合程序消费，却不适合人直接验收：用户需要自行根据 `asset_id` 查找原素材，再手动跳到 `start_sec`～`end_sec`，才能判断候选范围和模型理由是否准确。

本设计新增任务级离线验收页 `select-review.html`，让用户能够围绕某次 Brief 逐段播放候选并核对选片结果。

目标：

- 直观展示 Brief、分类覆盖、候选总时长和任务状态；
- 将候选关联到原素材，直接播放候选时间范围；
- 让用户连续切换候选并核对用途和理由；
- 保持页面完全只读，不修改选片状态或素材索引；
- 保持离线单文件交付，不要求启动本地服务。

## 范围

### 本次包含

- 每个选片任务生成独立的 `select-review.html`；
- 固定单播放器和候选列表；
- 候选区间播放、重新播放、上一条和下一条；
- 分类筛选、分类覆盖和运行进度展示；
- 缺失素材、不可播放格式和非法时间范围的只读降级；
- 选片成功后自动生成，以及对已有任务幂等重新生成；
- 自动测试和 `26shidu` 浏览器人工验收。

### 本次不包含

- 在页面中通过、驳回、调整或批注候选；
- 写回 `state.json`、`events.jsonl` 或 `cut_index.json`；
- 候选新增、更新、删除、主备切换或 `needs_review` 处理；
- 最终剪辑顺序、转场、音乐卡点或粗剪工程；
- 本地 Web 服务、后端 API 或浏览器持久化状态；
- 改造项目级 `exports/review.html`；
- 票据 02 的自主修订能力或票据 03 的恢复、重走能力。

## 方案选择

### 方案一：独立任务级离线页面（采用）

为每个选片任务生成独立页面。页面只消费该任务的 Brief 和状态，并从项目索引补全素材信息。多个 Brief 互不干扰，页面职责清楚。

### 方案二：扩展项目级 `review.html`（不采用）

代码复用较多，但项目素材分析与某次 Brief 的选片结果会混在一起。同一项目存在多个选片任务时，页面归属和导航都会变得含糊。

### 方案三：本地审阅服务（不采用）

播放器控制最灵活，但引入常驻进程和服务生命周期，不符合当前只读离线验收需求。

## 产物与路径

选片任务目录为：

```text
projects/<slug>/selections/<task>/
├── brief.md
├── state.json
├── events.jsonl
└── select-review.html
```

`select-review.html` 内嵌渲染所需的选片结果和素材元数据，不内嵌视频文件本体。视频使用本地文件 URI，因此 HTML 保持轻量。

新增路径辅助函数负责返回：

```text
projects/<slug>/selections/<task>/select-review.html
```

任务名沿用现有选片任务目录名，不建立第二套名称规范。

## 页面信息结构

### 顶部任务摘要

展示：

- Brief 标题和完整正文；
- `running` 或 `completed` 状态；
- 目标时长；
- 主选候选按时间并集计算后的总时长；
- 候选数量；
- 必要分类覆盖情况；
- 素材分页浏览进度，例如 `13/13`；
- 已读取完整详情的素材数量；
- `unresolved` 高优先级问题。

`unresolved` 非空或必要分类未覆盖时使用醒目警告。页面允许展示 `running` 状态，便于对已有中间产物进行只读诊断，但不会提供恢复操作。

### 中部验收工作区

采用“固定单播放器＋候选列表”布局：

- 左侧固定一个媒体播放器；
- 右侧按 `state.candidates` 原顺序平铺候选；
- 候选条目显示编号、文件名、起止时间、片段时长和分类标签；
- 分类筛选只隐藏或显示条目，不重排候选；
- 一条候选属于多个分类时仍只出现一次；
- 当前候选有明确选中状态；
- 页面明确提示候选数组顺序不是最终剪辑时间线。

不为每条候选创建独立播放器，避免同时加载多个本地视频，并保持比较时的视觉焦点。

### 当前候选详情

展示：

- `candidate_id`；
- 来源 `asset_id`、文件名和本地路径；
- `start_sec`、`end_sec` 和片段时长；
- 所属分类名称及分类用途；
- `recommended_use`；
- 完整 `reason`；
- 打开原文件的链接。

## 播放行为

用户点击候选后：

1. 播放器加载对应原视频；
2. 元数据就绪后跳到 `start_sec`；
3. 用户主动点击播放；
4. 播放到 `end_sec` 时自动暂停并停在当前候选；
5. 不自动切换下一候选。

控制按钮：

- `重新播放`：跳回当前候选 `start_sec` 并播放；
- `上一条`：切换到前一个当前筛选结果中的候选；
- `下一条`：切换到后一个当前筛选结果中的候选。

切换候选默认只定位，不自动播放。首尾候选对应的上一条或下一条按钮禁用，不循环跳转。

浏览器的 `timeupdate` 负责普通边界暂停，同时监听 `seeking`：如果用户拖到候选区间外，播放器将位置约束回 `[start_sec, end_sec]`。允许用户在候选区间内自由拖动。

## 数据读取与关联

渲染器读取：

```text
brief.md ─────────────┐
state.json ───────────┼─→ 按 asset_id 关联 ─→ 页面上下文 ─→ select-review.html
cut_index.json ───────┘
```

关联规则：

- `state.candidates[*].asset_id` 必须按 ID 查询 `cut_index.assets`；
- 文件名、媒体类型、缩略图和原素材路径来自匹配的 `Asset`；
- 分类名称和用途来自 `state.categories`；
- 总时长必须使用与完成校验一致的“同素材重叠区间按并集合并”算法，不能简单相加；
- 渲染器只读取源文件，不补写缺失字段。

素材路径按以下顺序解析，命中第一项后停止：

1. `asset.path`：绝对路径直接使用，相对路径以 `source_folder` 为基准；
2. `asset.relative_path`：以 `source_folder` 为基准；
3. `asset.file`：绝对路径直接使用，相对路径以 `source_folder` 为基准；
4. `asset.filename`：以 `source_folder` 为基准。

最终写入 HTML 的本地链接使用正确转义的文件 URI。候选关联到素材但上述字段都为空时，按“源文件不可访问”降级。

## 生成时机与命令

### 自动生成

`tripclipper select` 成功完成后，在 Runner 返回结果之前调用渲染器。CLI 在现有完成摘要中增加：

```text
审阅页面: <绝对路径>/select-review.html
```

页面生成失败不回滚已经完成的 `state.json`，也不改变任务状态。Runner 捕获渲染异常并通过结果对象返回 `review_html_path=None` 和 `review_error`；CLI 保持退出码 0，同时输出明确警告：选片已成功，但审阅页生成失败，并保留底层错误原因。

### 幂等重新生成

新增命令：

```text
tripclipper select-review <slug> <task-name> [--base-dir PATH] [--open]
```

- 命令只读取现有任务和项目索引；
- 多次执行覆盖同一 `select-review.html`，结果确定且不修改输入；
- `--open` 使用系统默认浏览器打开生成文件；
- 任务目录、`state.json`、`brief.md` 或 `cut_index.json` 缺失时返回清楚的非零错误；
- 该命令不启动、恢复或重走 LLM Agent。

## 代码边界

建议新增：

```text
src/tripclipper/clip_selection/review.py
src/tripclipper/clip_selection/templates/select-review.html.tmpl
```

并只修改：

- `src/tripclipper/paths.py`：选片审阅页路径；
- `src/tripclipper/clip_selection/runner.py`：完成后生成页面并在结果中返回路径；
- `src/tripclipper/cli.py`：显示自动生成结果并增加 `select-review` 命令；
- `pyproject.toml`：打包 HTML 模板；
- 对应测试和必要的 README 用法说明。

不改造 `src/tripclipper/exporter.py` 和现有 `review.html.tmpl`。安全处理规则可以在选片渲染器中用小型局部函数实现；不为少量共享代码进行跨模块重构。

## 安全与只读保证

- Brief、文件名、分类、用途和理由等所有用户或模型文本必须经过 HTML 转义；
- 内嵌 JSON 中的字面 `</script>` 必须替换为 `<\/script>`；
- 页面不嵌入 API Key、Codex 认证信息或模型配置；
- 页面 JavaScript 不发送网络请求；
- 页面不使用 `localStorage`、IndexedDB 或文件写入 API；
- 渲染前后 `cut_index.json`、`state.json`、`brief.md` 和 `events.jsonl` 内容保持不变；
- 唯一允许写入的文件是目标 `select-review.html`。

## 降级与错误处理

- `asset_id` 在索引中不存在：保留候选条目，显示“素材索引不存在”，禁用播放；
- 原视频文件不存在：显示文件路径和“源文件不可访问”，其他候选继续可用；
- 浏览器不支持媒体格式：显示浏览器错误提示和“打开原文件”链接；
- `start_sec`、`end_sec` 非法或超出素材时长：显示时间范围错误，禁用播放；
- 缩略图不存在：使用无预览占位，不影响视频播放；
- 非视频素材：显示静态预览或类型提示，不伪装成可进行区间播放的视频；
- 单条候选关联失败不得阻断整页生成；
- 模板读取或目标文件写入失败属于页面生成失败，由 CLI 明确报告。

## 自动测试

测试使用手工构造的 `cut_index.json`、`state.json` 和 Brief，不调用网络或真实模型。

覆盖：

1. 路径函数返回任务目录下的 `select-review.html`；
2. 渲染结果包含 Brief、状态、分类、候选和正确的素材文件名；
3. 多分类候选只渲染一个列表条目；
4. 总时长对同素材重叠范围按并集计算；
5. 素材 ID 正确关联本地文件 URI；
6. HTML 特殊字符和 `</script>` 被安全处理；
7. 缺失素材、缺失视频、非视频和非法时间范围产生预期降级；
8. 页面包含单播放器、候选列表、分类筛选和边界暂停逻辑；
9. 上一条、下一条和重新播放逻辑不启用自动连续播放；
10. 自动生成失败不改变已完成状态；
11. `select-review` 对已有任务可幂等重新生成；
12. 生成前后所有输入文件的内容哈希一致。

## 人工验收

使用项目 `26shidu` 和任务 `30秒欢快快剪`：

1. 记录 `cut_index.json`、`state.json`、`brief.md` 和 `events.jsonl` 哈希；
2. 生成 `select-review.html` 并在浏览器打开；
3. 确认顶部显示 30 秒目标、5 个候选、4 个分类和完整浏览进度；
4. 逐条点击五个候选，确认加载正确原视频；
5. 确认播放器从候选 `start_sec` 定位，并在 `end_sec` 自动停住；
6. 确认重新播放、上一条、下一条和分类筛选可用；
7. 确认候选用途、理由、分类和时间范围与 `state.json` 一致；
8. 重新计算输入文件哈希，确认全部未变。

## 完成标准

- 用户无需打开 JSON 或手工查找素材即可逐段验收候选；
- 页面只读、离线、单文件，视频引用本地原素材；
- 播放边界和候选信息与 `state.json` 一致；
- 自动生成与幂等重新生成均可用；
- 输入状态和素材索引在生成前后完全不变；
- 没有引入票据 02、03 的状态修改或恢复能力。
