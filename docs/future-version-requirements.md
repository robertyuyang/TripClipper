# TripClipper 后续版本需求路线图

本文档用于沉淀 MVP 之后的版本规划。MVP 产品需求和技术设计见：

```text
docs/mvp-product-requirements.md
docs/mvp-technical-design.md
```

MVP 的边界是：本地启动页、两阶段分析、可迁移 JSON/CSV/Markdown/HTML 数据包、Eagle 素材级写入。后续版本都应该基于这份可迁移数据包继续演进，而不是把 Eagle 或某个具体剪辑软件变成唯一事实源。

## 1. 路线原则

- Eagle 是第一个素材管理适配器，不是唯一事实源。
- `cut_index.json` 或它的后续形态，是稳定的机器可读项目索引。
- 自动化能力要逐步增加，任何难以撤销的操作都必须先有预览、dry-run 或项目副本。
- 剪辑风格、成片类型、目标时长、声音偏好都应该是项目输入，不写死在产品逻辑里。
- 永远保护原始素材。后续版本可以生成派生片段，但不能修改原文件。
- 每个大功能即使不接入剪映/CapCut 自动化，也应该独立有用。

## 2. 版本地图

```text
MVP / v0.1
  本地启动页、素材扫描、mock/模型分析、通用数据包、Eagle 素材级同步。

v0.2
  真实项目稳定性：断点续跑、失败重试、样本确认、单素材重跑。

v1.0
  轻量审核工作台：修改标签、星级、场景、推荐片段，再同步 Eagle 或导出。

v2.0
  粗剪副驾：生成 1-3 个粗剪方案和剪映/CapCut 友好的编号素材包。

v3.0
  声音和字幕 Agent：语音转写、说话人整理、SRT 导出、原声和 BGM 建议。

v4.0
  剪映/CapCut 自动化实验：只在项目副本中生成草稿，不直接操作用户真实项目。

v5.0
  个人偏好学习：学习用户对评分、标签、节奏、人物/空镜比例、开头方式的偏好。

v6.0+
  多工具和素材库扩展：非 Eagle 素材管理工具、长期归档、跨项目检索。
```

## 3. v0.2：真实项目稳定性

### 目标

让 MVP 能稳定用于多次真实项目，尤其是几百个视频的大素材量项目。

### 核心能力

- 支持中断后继续扫描和分析。
- 支持重新分析单个素材、单个文件夹、失败素材或选中素材。
- 全量模型分析前，先查看样本分析结果。
- 每个项目保存 prompt、模型和分析参数。
- 增加结构化运行日志，例如 `run_log.json`。
- 增加更清晰的失败清单，例如 `failed_assets.csv`。
- 启动前检查 ffmpeg、ffprobe、Eagle API、模型凭证和素材目录权限。
- 改进 `review.html`，支持按星级、标签、用途、场景、声音策略筛选。

### 输出和接口

- `run_log.json`：结构化任务日志。
- `failed_assets.csv`：失败素材清单。
- CLI/API 支持：
  - 重跑失败项
  - 重跑指定素材
  - 重跑样本分析
  - 只重新导出报告

### 验收标准

- 500 个视频项目被中断后，不需要从零开始。
- 失败素材可以单独重试，不影响已成功素材。
- 用户能先检查样本分析，再决定是否全量跑模型。
- 缺失依赖能在长任务开始前被清楚提示。

## 4. v1.0：轻量审核工作台

### 目标

从只读报告升级到可编辑的本地审核工作台，但仍然不做完整剪辑软件。

### 核心能力

- 浏览素材缩略图、标签、星级、场景、说明和分析状态。
- 修改素材级字段：场景、星级、标签、说明、是否入选、是否同步 Eagle。
- 修改片段级字段：in/out、用途、推荐理由、声音策略、是否入选。
- 支持批量操作：
  - 将 4 星以上素材标记为入选
  - 降低抖动/低质量素材评级
  - 给选中素材批量添加或移除标签
  - 将选中素材标记为待同步 Eagle
- 用户修改写回项目数据包。
- 修改后可重新导出 CSV、Markdown、HTML 和 Eagle 同步计划。

### 输出和接口

- 仍通过 `tripclipper serve` 打开本地页面。
- 项目状态继续保存在可迁移项目数据包中。
- 所有导出物都从用户审核后的状态重新生成。

### 非目标

- 不做时间线编辑器。
- 不生成最终视频。
- 不直接操作剪映/CapCut 时间线。

### 验收标准

- 用户可以在同步 Eagle 前修正标签、星级、场景和推荐片段。
- 用户编辑在服务重启后仍然存在。
- 导出结果反映用户修改，而不是只反映模型原始输出。

## 5. v2.0：粗剪副驾

### 目标

基于已分析、已审核的 `cut_index` 数据，生成可执行的粗剪方案，减少用户在剪映/CapCut 里手动挑素材的时间。

### 核心能力

- 根据项目意图和审核后的素材，生成 1-3 个粗剪方案。
- 按目标时长、节奏、片段用途、场景平衡、人物偏好、声音偏好和星级选择片段。
- 输出粗剪顺序，包含 in/out、用途、推荐理由、声音策略和预计总时长。
- 导出剪映/CapCut 友好的编号素材包。
- 可选生成低风险的片段小样或预览片段。
- 生成标题、地点字幕、说明字幕建议，但不强制生成完整字幕文件。

### 输出和接口

- `rough_cut_plans.json`
- `rough_cut_plan_1.csv`、`rough_cut_plan_2.csv` 等。
- `rough_cut_plan_1.md`：给人看的方案说明。
- 可选：`exports/numbered_assets/`
- 可选：简易 EDL 风格文本，为未来自动化做准备。

### 非目标

- 不自动生成最终成片。
- 不直接修改剪映/CapCut 项目。
- 不做复杂转场、调色、特效或 BGM 混音。

### 验收标准

- 给定审核后的素材和目标时长，工具至少能生成一个连贯的粗剪方案。
- 粗剪方案包含预计时长和每段素材的选择理由。
- 编号素材包可以被用户手动拖进剪映/CapCut。
- 用户修改项目意图或入选素材后，可以重新生成方案。

## 6. v3.0：声音和字幕 Agent

### 目标

把原声、人声、字幕和 BGM 建议变成剪辑准备流程中的一等能力。

### 核心能力

- 对人声较多的素材进行语音转写。
- 为选中的语音片段导出 `.srt` 字幕。
- 标记可保留的原声：发言、笑声、掌声、环境声、音乐、噪音。
- 给出声音策略：
  - 保留同期声
  - 保留环境声并压低 BGM
  - 静音后使用 BGM
  - 人声处降低 BGM
  - 因噪音明显建议弃用
- 在可行时支持说话人整理和说话人标签。
- 生成旅行地点、活动环节、重要时刻的短字幕建议。

### 输出和接口

- `transcripts/`：转写产物目录。
- `subtitles/`：`.srt` 字幕导出目录。
- `audio_plan.csv`
- 音频字段进入 `cut_index.json` 和 `segments.csv`。

### 非目标

- 不自动完成最终混音。
- 不做 BGM 素材市场或自动版权处理。
- 不修改原始音频。

### 验收标准

- 能识别语音片段并导出字幕文件。
- 用户能快速筛选“原声可用”的素材。
- 声音策略在审核页和粗剪方案中都可见。

## 7. v4.0：剪映/CapCut 自动化实验

### 目标

基于已审核的粗剪方案，实验性生成可编辑的剪映/CapCut 草稿，但只能写入项目副本或导出目录。

### 核心能力

- 研究剪映/CapCut 桌面端草稿结构或可用导入/导出路径。
- 在可行时，根据粗剪方案生成草稿项目副本。
- 插入选中素材和近似 in/out。
- 在支持时插入标题或字幕占位轨道。
- 写入前必须有预览或 dry-run。
- 在隔离导出目录中验证生成结果。

### 输出和接口

- `capcut_draft_plan.json`
- `exports/capcut_draft_copy/`
- `capcut_automation_report.md`

### 安全要求

- 绝不原地修改用户真实剪映/CapCut 项目。
- 始终写到新项目副本或导出目录。
- 实验性自动化产物必须明确标记。
- 如果草稿结构或 UI 自动化不稳定，回退到编号素材包和粗剪 CSV。

### 验收标准

- 对受控测试项目，工具能生成安全草稿副本，或清楚说明为什么不能生成。
- 草稿生成失败不会影响本地项目数据、Eagle 同步或粗剪导出。

## 8. v5.0：个人偏好学习

### 目标

从用户修正和最终选择中学习，让后续项目更符合用户自己的剪辑审美。

### 核心能力

- 记录用户对标签、星级、入选片段和粗剪方案的修改。
- 学习评分校准：
  - 用户经常上调什么素材
  - 用户经常下调什么素材
  - 常见误判类型
- 学习风格偏好：
  - 人物和空镜比例
  - 常用开头方式
  - 常用转场类型
  - 原声使用习惯
  - 不同成片类型下的节奏偏好
- 维护可复用偏好档案，例如旅行 vlog、团队活动、家庭记录、会议回顾。
- 在分析和粗剪规划时，把偏好档案作为上下文。

### 输出和接口

- `profiles/<profile_name>.json`
- 项目报告中展示本次使用的偏好摘要。
- UI 支持选择、更新和关闭偏好档案。

### 隐私和控制

- 偏好档案默认保存在本地。
- 用户可以查看、编辑、导出或删除偏好档案。
- 偏好学习必须可配置，不能强制开启。

### 验收标准

- 一个项目中的用户修正能改善后续项目的推荐。
- 偏好数据可查看、可编辑。
- 关闭偏好学习后，系统恢复基础推荐逻辑。

## 9. v6.0+：多工具和长期素材库

### 目标

让 TripClipper 不再绑定 Eagle，而是成为个人长期素材智能层。

### 核心能力

- 支持导入/导出到其他素材管理工具。
- 支持 sidecar 元数据文件，方便工具无关工作流。
- 支持跨项目搜索：标签、场景、地点、人物、人声、用途。
- 生成长期归档报告和项目对比。
- 可选支持视觉相似检索，寻找重复或近似片段。
- 可选建立本地 embedding 索引，支持文本和视觉检索。

### 输出和接口

- 素材管理工具适配器接口。
- sidecar 导出格式。
- 跨项目索引。
- 搜索 UI 或 CLI。

### 非目标

- 默认不做云端素材托管。
- 不做多人协作，除非后续明确立项。

### 验收标准

- 项目元数据可以导出给至少一个非 Eagle 目标。
- 即使用户不再使用 Eagle，元数据仍然可用。
- 跨项目搜索能找到可复用镜头、地点和素材模式。

## 10. 版本依赖关系

- v0.2 依赖 MVP 的数据包和扫描/分析/导出管线。
- v1.0 依赖稳定的项目状态持久化。
- v2.0 依赖已审核的片段级数据。
- v3.0 依赖稳定的音频提取和转写接口。
- v4.0 依赖粗剪方案和严格安全边界。
- v5.0 依赖可编辑审核状态和用户修改记录。
- v6.0 依赖稳定的工具无关元数据和适配器边界。

## 11. 不应拉进 MVP 的内容

以下能力很有价值，但不应进入第一版，除非重新明确调整范围：

- 完整审核工作台。
- 正式粗剪方案生成。
- 片段裁切和编号素材包。
- SRT 字幕生成。
- 剪映/CapCut 草稿写入。
- 个人偏好学习。
- 跨项目搜索。
- SQLite 迁移。
- 非 Eagle 适配器。

这些能力应该作为后续版本推进。如果拉进 MVP，会模糊第一版边界，拖慢第一个可用版本。
