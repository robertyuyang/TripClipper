# ADR-002: M4 默认候选池采用确定性后处理（零 LLM）

- 状态：已采纳（grilling 拍板于 2026-06-28）
- 关联：M4 spec §默认剪辑候选池、CONTEXT.md §全局候选池入选状态
- 相关需求：PRD FR-6（[docs/mvp-product-requirements.md L758-L760](../mvp-product-requirements.md)）；TD 8

## 上下文

M4 完成雷同分组（ADR-001）后，下一步是生成**默认剪辑候选池**——即"用户打开 Eagle
时默认展示的剪辑筛选集合"。PRD FR-6 描述候选池的组成规则：

> 默认剪辑候选池应优先包含高星素材中的非雷同素材，以及每个高置信雷同素材组的**主选**素材。
> 同组备选素材即使是 4 星或 5 星，也默认标记为备选。
> 默认剪辑候选池应利用主体类型和景别做基础平衡，避免候选结果全是人物近景或全是风景空镜。
> 待人工确认素材应进入单独的待确认列表，不应混入默认主候选列表。

可选路径：

- **路径 1 — 确定性后处理**：M4 在拿到所有 `SimilarGroup` 之后，纯本地、纯规则做候选池：
  起始集 = 非雷同素材 + 组主选 → 主体×景别平衡修剪 → 写状态与中文 reason。
- **路径 2 — 候选池也走一次 LLM**：把所有素材的 summary/tags/rating/similar_group_id 打包丢给文本模型，
  让它直接选候选池并写 reason。
- **路径 1+2 同时支持，由 flag 切换** — 用户最初的偏好，已在 Q3 拒绝。

## 决策

**采用路径 1**（确定性后处理，不调用 LLM）。

具体形态：
- **起始集**：所有 `analyzed` 状态的素材中，`similar_selection ∈ {none, primary}` 的并集。
- **不截断**：不引入 `target_pool_size` 字段，不按总数硬截断。
- **主体×景别平衡修剪**：仅当 `候选池总数 ≥ 20` **且** 某一 `(subject_type, shot_scale)` 桶占比 > 50% 时触发；
  把该桶 rating 最低的素材降为 `alternate`，直到占比 ≤ 50%；修剪上限不超过候选池总数的 20%。
- **needs_review 处理**：所在雷同组置信度不足（含 ADR-001 仲裁失败）或 `analysis_status != analyzed` 的素材
  统一标 `edit_candidate_status="needs_review"`，**不进候选池也不进 alternate**。
- **edit_candidate_reason 模板化**：路径 1 的 reason 是中文模板（"非雷同高星" / "海边日落组主选" /
  "为景别平衡入选 alternate" / "所在雷同组置信度不足，待人工确认"），可读但非自然语言。

## 理由

1. **FR-6 候选池规则全是"规则可描述"的**：高星非雷同 + 组主选 + 主体/景别平衡——这三条都能用规则精确表达，
   不需要 LLM 判断"叙事流"这种主观维度（PRD 也没要求叙事流）。
2. **与 M3 纪律一致**：M3 只在"必须真模型才能完成"的事情上打模型；候选池组装是纯逻辑题，
   再花 token 既不增加质量也不增加可解释性（reason 模板已足够说明状态来源）。
3. **测试可离线**：M4 这一层全部纯函数可单元测试，与 ADR-001 的 Arbiter 形成明显边界——
   合成 30 条 fixture 可以完整覆盖平衡修剪所有分支，无需打模型。
4. **可观测性更强**：硬约束（"任何 `(subject_type, shot_scale)` 桶占比 ≤ 50%"）能直接断言，
   规则比 LLM 更可靠；而 LLM 输出的 reason 文案不可复现，回归测试只能靠真打模型。
5. **MVP 阶段无验证手段**：grilling Q3 时讨论过"两种都支持靠测试看效果"的想法，
   结论是 5 条真实素材 + 1 个雷同组无法形成对照实验，"靠测试看"不成立。

## 后果

### 正面

- `clusterer.py` 中候选池生成函数是纯函数；M4 测试套件因此只有 Arbiter 部分依赖真模型。
- 主体×景别平衡命中的"为什么这条被降"可硬断言。
- 路径 2（LLM 候选池）作为未来可选增强暂存——`docs/specs/M3-real-model-analysis-brainstorming/`
  同级目录可放，不实现。

### 负面

- `edit_candidate_reason` 文案机械（"非雷同高星" 而非 "这条海边远景适合做项目过渡镜头"）；
  若 M5/M6/M7 上线后用户反馈 reason 文案不够好，作为路径 2 的强需求触发点。
- 主体×景别平衡的阈值（≥20 + >50% + 修剪上限 20%）是经验值，可能在用户首批真实项目上需要微调。

## 替代方案及拒绝原因

- **路径 2（LLM 候选池）**：上述 5 条理由全部拒绝。
- **路径 1+2 同时支持**：grilling Q3 拒绝——两套候选池策略在 MVP 样本量下无法对照，
  双倍代码 + 双倍测试矩阵 + 双倍配置面，仅为"开关而开关"。

## 退出条件

若未来用户反馈以下任一情况，重新评估：
- `edit_candidate_reason` 文案被用户多次反映"看不懂为什么这条入选"；
- 主体×景别平衡阈值（≥20 + >50%）在真实项目上误伤明显（应入选的高星被错误降级）；
- 多次出现"叙事流"维度需要 LLM 判断的剪辑场景。
