# 多轮片段选片 Agent 设计

## 状态

本设计已完成方案讨论，等待用户复核。它只定义片段级选片 Agent，不修改正式评分 Prompt，不实现代码，也不改变现有 `cut_index.json` 的写入规则。

## 背景

TripClipper 当前由单素材视觉分析生成素材级字段和 `clip_suggestions`。在 `26shidu` 项目中，260 条素材已有 307 个建议片段，但这些建议来自一次模型分析；现有流程不会针对证据不足的素材继续观察，也不会依据目标视频的时长、风格和项目内重复关系，对所有片段做全局取舍。

评分档位拥挤与项目选片是两个不同问题：

- `rating` 应表达素材最佳片段自身的可见价值，保持相对稳定。
- 项目选片应表达片段在某次视频任务中的作用、稀缺性、替代关系和优先级，随目标时长与风格变化。

两者必须解耦。同一素材可以保持固定星级，但在不同视频任务中得到不同的选片结果。

## 目标

建立一个受控但具有自主搜索能力的片段级选片 Agent：

1. 读取现有 `cut_index.json` 和 `clip_suggestions`，不重复全量分析原始视频。
2. 由 LLM 自主判断哪些素材证据不足，并按需多次查看更多时间点。
3. 根据本次视频的时长、风格和叙事需要，动态确定需要覆盖的内容。
4. 在项目范围内比较片段，形成主选、备选、排除和待复核结果。
5. 使用独立、受 Schema 约束的 JSON 保存结果，不修改 `cut_index.json`。
6. 到片段备选池为止，不编排最终时间线。

## 非目标

- 不修改正式评分 Prompt 或生产评分规则。
- 不在本设计中完成五档评分量表的重新校准。
- 不直接修改或扩充 `cut_index.json` 中的 `clip_suggestions`。
- 不决定最终片段顺序、精确剪点、音乐卡点和转场。
- 第一版不实现多角色并行评审。
- 第一版不实现把 Agent 新发现晋升回固定素材分析的流程。

## 核心架构

采用分层漏斗式多轮搜索。系统规定检查点和安全边界，Agent 决定检查点内部的搜索策略：

```text
cut_index.json + Selection Brief
              ↓
1. 全量索引感知与自主侦察规划
              ↓
2. 素材内自适应深挖
              ↓
3. 整理本次候选片段与证据
              ↓
4. 确定本次视频需要覆盖的内容
              ↓
5. 多对多归类并进行同类比较
              ↓
6. 容量与覆盖审计，必要时回退搜索
              ↓
7. 输出片段级备选池
```

这是一种有 Harness 的受控 Agent，而不是纯固定工作流：

- 固定的是全量可感知、证据可追踪、预算上限和结束检查。
- 自由的是查看哪些素材、查看哪些时间点、如何组织内容需要、比较哪些片段以及何时请求结束。

## 输入

### 固定素材输入

Agent 只读 `projects/<slug>/cut_index.json`，使用：

- 素材标识、路径、类型、时长和拍摄信息；
- 摘要、标签、人物、场景和镜头信息；
- 固定 `rating`；
- 原有 `clip_suggestions`；
- 分析状态、警告和失败信息；
- 已有缩略图、关键帧和时间戳。

`cut_index.json` 是初始世界模型，不被视为最终答案。Agent 可以怀疑现有证据是否充分，但不能直接改写它。

### Selection Brief

每次选片任务必须解析出：

- `target_duration_sec`：目标视频时长；
- `style`：视频风格；
- `audience`：目标受众，可为空；
- `people_focus`：人物重点，可为空；
- `audio_priority`：声音偏好，可为空；
- `max_review_clips`：本次最多交给人工复核的片段数。

字段可以由用户提供，也可以继承项目默认配置；进入 Agent 前必须得到确定值。

## 七步流程

### 1. 全量索引感知与自主侦察规划

系统保证所有素材都可以通过查询工具访问。Agent 根据 Selection Brief 和 `cut_index` 自主判断：

- 哪些现有片段证据已经充分；
- 哪些长视频抽帧过稀或建议片段为空；
- 哪些摘要、评分和时间范围互相矛盾；
- 哪些素材可能与本次目标有关，但现有证据无法确认；
- 下一步把视觉调用预算投入到哪里最有价值。

本步骤调用 LLM 做规划，但不要求重新观看所有视频。

### 2. 素材内自适应深挖

Agent 可以自主调用工具：

- 查看已有关键帧；
- 请求某个时间范围的追加帧；
- 缩小或扩大观察范围；
- 比较同一素材内多个疑似片段；
- 在证据充分、预期收益不足或预算受限时停止查看。

系统只限制可访问项目、调用预算和时间范围合法性，不预先指定 Agent 必须查看哪些素材。

### 3. 整理本次候选片段与证据

Agent 将原有建议片段与本次新找到的片段整理为统一的待比较集合。每个片段至少包含：

- `asset_id`；
- `in` / `out`；
- 来源是原有 `clip_suggestions` 还是本次 Agent 新发现；
- 实际看到的事实；
- 技术限制；
- 原有建议片段可记录其固定星级快照；本次新发现的片段没有固定星级时保持为空，不临时发明星级。

这只是本次运行中的候选集合，不写回固定素材层。

### 4. 确定本次视频需要覆盖的内容

LLM 根据 Selection Brief 和实际可用素材，制定本次视频需要覆盖的内容清单，例如开场吸引点、活动过程、人物反应、叙事交代或情绪收尾。

内容清单不是固定枚举，必须满足：

- 每项能说明对当前视频的作用；
- 区分必要项和可选项；
- 数量与目标时长相称；
- 允许记录当前没有合适素材；
- 不允许为每个片段单独创建分类以逃避横向比较。

内容清单是可调整计划。发现真正有价值的意外片段时，Agent 可以说明理由后修改清单。

### 5. 多对多归类并进行同类比较

片段与内容分类是多对多关系：

- 一个内容分类可以有多个候选片段；
- 一个片段可以属于零个、一个或多个分类；
- 未归类不等于低价值，也不是候选池准入门槛。

Agent 在同类片段中比较可见价值、风格匹配、重复程度和替代关系：

- 已理解且有价值但未成为主选的片段进入 `alternate`；
- 未归类但有趣、当前用途不确定的片段可以进入 `alternate`；
- 只有确认低价值、技术不可用或高度重复时才进入 `excluded`；
- 模型无法可靠判断但可能有趣、稀有或不可替代时进入 `needs_review`。

低星片段可以因承担唯一叙事作用成为主选；高星片段也可以因高度重复成为备选。

### 6. 容量与覆盖审计

Agent 检查：

- 所有必要内容是否有主选，或已明确记录缺失；
- 重复片段是否形成清楚的主选和备选关系；
- 未归类但有趣的片段是否被重新审视；
- 是否仍有值得继续调查的高优先级问题；
- 主选片段可用总时长是否与目标视频容量匹配。

发现缺口时，Agent 可以回到步骤 1、2 或 4，继续搜索或调整内容清单。

### 7. 输出片段级备选池

输出：

- `primary`：当前任务主选；
- `alternate`：已确认有价值的备选；
- `excluded`：确认不推荐；
- `needs_review`：可能有价值但模型无法可靠判断。

每个结果必须带时间范围、来源、可见证据、项目作用、选择理由和替代关系。输出不包含最终时间线顺序。

## 两类余量

### 容量余量

第一版使用固定的 50% 主选余量。设目标时长为 `T`：

```text
T <= 主选片段可用总时长 <= 1.5T
```

例如 45 秒视频的主选片段总时长控制在 45 至约 68 秒。`alternate` 和 `needs_review` 不计入该上限。

同一片段属于多个内容分类时只计算一次；同一素材内主选范围发生重叠时，按时间范围并集计算，避免重复累计。

该比例是待实验校准的初始系统参数，不写入 Prompt，也不由 LLM 自行决定。严格的时间线可行性仍由后续粗剪阶段验证。

### 不确定性余量

`needs_review` 单独承载可能有趣、稀有或不可替代但证据不足的片段。Agent 必须先尝试通过追加查看解决不确定性；只有继续调用仍无法确认或预算耗尽时，才交给人工复核。

每条 `needs_review` 必须说明：

- 为什么可能有价值；
- 当前无法确认什么；
- 人工需要重点查看什么。

人工复核数量不得超过 Selection Brief 中已经确定的 `max_review_clips`，不挤占主选容量。该数值是运行参数，不由 LLM 在执行中自行扩大。

## 结束条件

### 正常结束

Agent 只能提交结束请求，最终由程序检查。以下条件必须同时满足：

1. 所有 `cut_index` 素材都进入过可查询和考虑范围，但不要求全部重看原视频。
2. 每个必要内容分类都有主选，或明确记录没有找到。
3. 同类重复片段已经形成主选和备选关系。
4. 所有未归类但有趣的片段已经复查。
5. 主选可用总时长位于 `T` 至 `1.5T`。
6. 不存在尚未处理的高优先级调查问题。
7. 完整审计一轮后，候选结构没有变化。
8. 输出通过 Schema 和业务规则校验。
9. `needs_review` 数量不超过 `max_review_clips`；超出时必须继续调查或完成取舍。

“候选结构没有变化”指没有新增片段、状态变化、分类变化、归属变化或重新出现的必要内容缺口；只修改理由文字不算结构变化。

### 强制结束

达到调用预算或最大循环次数时必须停止。系统仍保存当前有效结果，但标记为未完整完成，并列出未解决内容，不得伪装为正常收敛。

## 独立数据边界

选片 Agent 不修改 `cut_index.json`，而是写入自己拥有的结果目录：

```text
projects/<slug>/selections/<selection-id>.json
```

结果文件与 `cut_index.json` 配合使用，不复制完整素材信息。它通过 `asset_id` 和时间范围引用基础素材，并保存本次任务新增的信息。

建议的顶层结构：

```json
{
  "schema_version": 1,
  "selection_id": "...",
  "project_slug": "26shidu",
  "source_cut_index": "projects/26shidu/cut_index.json",
  "source_cut_index_sha256": "...",
  "brief": {},
  "run_status": "completed",
  "clips": [],
  "unresolved": []
}
```

系统字段、源文件哈希和运行状态由程序填写，不能由 LLM 声称。源哈希用于发现选片结果与后续改动过的 `cut_index` 不再匹配。

片段记录至少包含：

- `asset_id`、`in`、`out`；
- `source`：`cut_index` 或 `selection_agent`；
- `status`：`primary`、`alternate`、`excluded`、`needs_review`；
- 可见事实与技术限制；
- 原有建议片段的固定星级快照，可为空；
- 零个或多个内容分类；
- 项目作用、选择理由和替代关系；
- 待复核原因与人工查看重点，可为空。

## LLM 与文件写入边界

LLM 不获得任意文件写权限，也不直接生成最终文件。它只能调用受控提交工具：

```text
LLM 提交结构化参数
→ 程序按固定 Schema 校验
→ 程序执行业务校验
→ 校验通过后原子写入 JSON
```

程序必须校验：

- `asset_id` 存在于配套 `cut_index`；
- 时间范围合法且不超过素材时长；
- 枚举值合法；
- 必填字段完整且不存在未知字段；
- 重复片段、重叠范围和替代引用有效；
- 正常结束条件成立。

校验失败时返回具体错误，允许有限次数修正。仍失败则保留最后一个有效状态并停止，不产生半截 JSON。

## Agent 工具边界

第一版只需要以下能力：

- 查询素材索引；
- 读取某条素材的现有分析和建议片段；
- 查看已有关键帧；
- 请求指定时间范围的追加帧；
- 提交或更新本次候选片段；
- 提交内容分类及片段归属；
- 提交主选、备选、排除和待复核判断；
- 请求结束并接受程序检查。

工具只能访问当前项目，读取原始素材和 `cut_index`，写入选片 Agent 的结果目录。

## 技术架构与对照实现

选片 Agent 使用显式 Harness 循环，不把七步产品流程编码成固定状态机：

```text
Runner 启动 Harness
  ↓
Harness 提供 Prompt、当前状态和 Tool 契约
  ↓
LLM 自主选择一个 Tool
  ↓
Tool 执行查询、范围查看或状态提案
  ↓
校验并原子保存检查点
  ↓
返回 observation，进入下一轮
```

七步是 Agent 的任务目标和结束审计依据，不规定每轮调用顺序。Agent 可以重复查看素材、回到分类、修改候选和重新比较。

为比较状态所有权，保留两种 Harness：

- Agent 主导状态：合法状态 Tool 直接提交，结束时统一检查完整业务条件。
- Policy 保护状态：Agent 提交状态提案，`SelectionPolicy` 在每次变化前检查；失败只返回 observation，不改变已保存状态。

两者都有拆分后的 `agent.py`、`tools.py`、`harness.py`、`models/contracts.py` 和 `store.py`。文件是否拆分不是架构差异；真正差异是状态变化由 Agent 直接决定，还是由 Policy 逐次批准。

当前对照实现位于：

```text
experiments/clip_selection/minimal_agent_owned/
experiments/clip_selection/minimal_policy_guarded/
experiments/clip_selection/production_agent_owned/
experiments/clip_selection/production_policy_guarded/
```

生产版本使用独立选片 Prompt 和 JSON 动作协议，不调用或修改现有 `Provider` 正式 Prompt。它读取现有模型配置和 `cut_index`，把范围查看得到的帧送入下一轮模型，并在每轮原子保存独立选择文件。

## 错误与恢复

- 单次视觉调用失败：记录失败并允许 Agent 调整搜索策略，不丢弃已验证结果。
- 时间码无效：拒绝该片段，要求重新定位；不能静默修正。
- `cut_index` 在运行中变化：源哈希不匹配时停止最终写入，要求基于新版本重跑或人工确认。
- 预算耗尽：按强制结束规则输出当前有效结果和未解决项。
- LLM 输出不符合 Schema：拒绝写入并返回字段级错误。
- 运行中断：已通过程序校验的中间状态可恢复，未验证的模型文本不作为结果。

## 验证设计

### 第一阶段：固定样本离线验证

从 `26shidu` 选择能够覆盖以下情况的固定样本：

- 已有 `clip_suggestions` 且证据充分；
- 长视频抽帧稀疏；
- `clip_suggestions` 为空；
- 高星但高度重复；
- 低星但承担唯一叙事作用；
- 短暂、有趣、可能被均匀抽帧遗漏；
- 模型无法确认、需要人工复核。

人工先建立片段级参考结果，再运行 Agent。禁止用目标比例要求 Agent 控制结果数量。

### 关键指标

- 新高价值片段召回：人工认为值得保留但原 `clip_suggestions` 未覆盖的片段，被 Agent 找到的比例。
- 高价值误排除：人工认为应主选或备选的片段被 Agent 排除的比例。
- 重复压缩效果：同类重复片段是否形成合理主备，而非全部进入主选。
- 必要内容覆盖：人工确认的必要内容是否被主选覆盖，或被正确标记为缺失。
- 未归类趣味片段保留：有趣但不属于初始分类的片段是否仍进入备选或促使计划调整。
- `needs_review` 有效性：人工复核项中真正存在价值或不确定性的比例，以及复核总量。
- 成本：视觉调用次数、追加帧数量和每项目总耗时。
- 可复现性：相同输入重复运行时，主选集合和结构性判断的稳定程度。

### 第二阶段：端到端对照

使用同一 Selection Brief 对比：

1. 现有一次分析后直接按素材级评分和候选状态选片；
2. 新多轮片段选片 Agent。

人工盲评比较两者的片段覆盖、重复度、遗漏高光、复核负担和最终粗剪可用性。

### 成功标准

- 不降低人工确认的关键高光召回；
- 明显减少重复主选；
- 能保留低星但必要的叙事片段；
- 未归类趣味片段不会因分类缺失被自动排除；
- `needs_review` 数量在设定人工预算内；
- 预算耗尽和数据不一致时能够明确输出未完成状态；
- 全程不修改正式 `cut_index.json` 和生产评分 Prompt。

## 与评分档位设计的关系

本 Agent 读取固定星级，但不负责修订星级语义。新的五档评分量表需要独立设计和独立人工基准。两项工作只通过稳定接口连接：

- 评分提供片段自身价值信号；
- 选片 Agent 结合 Selection Brief、内容覆盖、重复性和稀缺性做项目级决策；
- 选片结果不能反向改写固定星级。

## 演进路径

第一版采用单个通用 Agent 的分层漏斗。未来如需升级为多角色评审，可在步骤 4 至 6 增加高光、叙事覆盖、风格匹配和技术质量评审器，并由统一仲裁层合并提案。只要结构化输入输出和来源字段保持稳定，无需推翻本设计的存储与工具边界。
