### 2026-06-23：大模型分析模块未询问 API Key

- 日期：2026-06-23
- 任务背景：项目中涉及大模型分析模块，需要真实调用或配置模型服务能力。
- 错误表现：Codex 没有向使用者确认或询问 API Key、模型服务配置等必要信息，而是直接写了 mock 代码，并且没有明确告知这是 mock 实现。
- 影响：使用者可能误以为功能已经具备真实分析能力，后续集成或测试时才发现行为与预期不符，增加排查成本。
- 修正方式：涉及外部模型、付费服务、凭证或运行时配置时，应先明确询问配置来源，或清楚说明当前实现是 mock / stub / placeholder，并标注后续接入点。
- 复盘结论：不能把 mock 当成默认答案悄悄塞进项目。只要行为不是生产可用实现，就必须显式说明边界、风险和替换方式。

### 2026-06-23：项目上下文丢失后从通用角度回答

- 日期：2026-06-23
- 任务背景：对话已经建立在具体项目目录下，本应优先读取和利用项目上下文。
- 错误表现：Codex 即使在项目下建立的对话中，也有概率丢失当前项目上下文，从通用角度回答问题，而不是结合已有文件、设计文档和代码结构。
- 影响：回答可能偏离项目真实状态，给出泛化建议、重复已有设计，或忽略当前代码库中的约束和约定。
- 修正方式：回答项目相关问题前，应优先确认当前工作目录、读取关键文件，并在必要时说明基于哪些项目文件得出结论。
- 复盘结论：项目内对话不能默认等于已经掌握项目。任何涉及实现、架构、需求或调试的问题，都应重新锚定到当前仓库上下文。
